**Task decomposition** is the process by which an AI orchestrator parses a complex goal into discrete, executable subtasks — each with defined inputs, expected outputs, and dependencies — enabling multi-agent workflows where specialists handle their appropriate portions in parallel and sequence.

Task decomposition is one of the most important capabilities of an AI orchestrator. The quality of decomposition determines whether a complex mission is handled efficiently (with appropriate parallelization and clear task boundaries) or inefficiently (with bottlenecks, repeated work, or ambiguous agent assignments).

## How Task Decomposition Works

**1. Goal parsing:** The orchestrator receives a natural language mission and extracts the underlying objectives. "Research our top 5 competitors and draft a competitive strategy update" becomes two primary objectives: (1) gather competitive intelligence, (2) synthesize into a strategic document.

**2. Subtask identification:** Each objective is broken into specific, actionable subtasks. Objective 1 becomes: identify the 5 competitors, then research each competitor individually (company overview, product features, pricing, recent news, job postings).

**3. Dependency mapping:** The orchestrator identifies which tasks must complete before others can begin (dependencies) and which tasks can run simultaneously (parallelizable). Identifying competitors must happen before researching each — sequential. Researching each competitor is independent — parallel.

**4. Resource routing:** Each subtask is assigned to the appropriate specialist based on the task type. Research tasks → Scout agent. Writing tasks → Ghost agent. System operations → Forge agent.

**5. Execution scheduling:** The orchestrator creates tasks in the appropriate order, triggering parallel tasks simultaneously and holding sequential tasks until their dependencies complete.

## The Parallel Execution Advantage

Effective task decomposition enables dramatic time savings through parallelization. Researching 5 competitors sequentially takes 5x as long as researching them in parallel. For a mission requiring 20 parallel research tasks, parallelization reduces wall-clock time by up to 20x compared to sequential execution.

This is a fundamental advantage of multi-agent systems over single-agent systems: a single agent executes everything sequentially; an orchestrated team executes independent tasks simultaneously.

## Decomposition Quality

Good task decomposition:
- Creates tasks that are scoped to a single specialist's capability (not requiring multiple agent types)
- Identifies all parallelization opportunities (not serializing independent tasks unnecessarily)
- Provides each agent with all the context it needs (inputs are complete, not requiring agents to figure out what they need)
- Includes clear success criteria for each subtask (so the monitor agent can evaluate completion)

Poor task decomposition creates bottlenecks, unclear handoffs, and underutilized parallelization opportunities — resulting in slower, lower-quality multi-agent workflow execution.
